## Static And Interactive Components

Static components are best for reusable presentation: cards, callouts, status chips, signal meters, terminal snippets, and code examples. They produce normal HTML during the build.

Interactive components are for stateful reading surfaces: selectable cards, expandable lists, workflow graphs, metric graphs, and lazy media. The MDX page still imports an Astro wrapper; the wrapper owns the Svelte island and hydration directive.

## Create Your Own Component

Add reusable authoring components under `src/components/docs/`. Keep the public API simple: props should be plain strings, numbers, arrays, or data objects that are easy to pass from MDX.

This page uses `CodeBlock` to render every code sample. The component wraps Astro's syntax highlighter and adds an icon-only copy button in the top-right of the bounding rectangle.

<CodeBlock
	title="src/components/docs/CodeBlock.astro"
	lang="astro"
	code={String.raw`---
import { Code } from 'astro:components';

export interface Props {
	title?: string;
	code: string;
	lang?: string;
}

const { title, code, lang = 'text' } = Astro.props;
const codeText = code.trim();
const copyLabel = title ? 'Copy ' + title : 'Copy code';
---

<figure class="ria-code-block ria-terminal" data-ria-code-block>
	<figcaption>
		<span>{title ?? lang.toUpperCase()}</span>
		<button type="button" aria-label={copyLabel} title="Copy code" data-ria-copy-button>
			<svg aria-hidden="true" viewBox="0 0 24 24">
				<rect x="9" y="9" width="10" height="10" rx="2"></rect>
				<path d="M5 15V7a2 2 0 0 1 2-2h8"></path>
			</svg>
		</button>
	</figcaption>
	<Code code={codeText} lang={lang} theme="github-dark" />
</figure>

<script>
	function initCodeBlocks() {
		for (const root of document.querySelectorAll('[data-ria-code-block]:not([data-copy-ready])')) {
			root.setAttribute('data-copy-ready', 'true');
			const button = root.querySelector('[data-ria-copy-button]');
			const pre = root.querySelector('pre');
			button?.addEventListener('click', () => {
				navigator.clipboard?.writeText(pre?.innerText ?? '');
			});
		}
	}

	initCodeBlocks();
	document.addEventListener('astro:page-load', initCodeBlocks);
</script>`}
/>

## Nesting And Sections

Starlight routes follow the path under `src/content/docs/`.

- `src/content/docs/guides/capture-checklist.mdx` becomes `/guides/capture-checklist/`.
- `src/content/docs/guides/data/capture-checklist.mdx` becomes `/guides/data/capture-checklist/`.
- `src/content/docs/reference/use-components-in-a-new-doc.mdx` becomes `/reference/use-components-in-a-new-doc/`.

The current sidebar autogenerates `guides/` and `reference/` from `astro.config.mjs`. To add a new top-level section, create a folder under `src/content/docs/` and add a matching sidebar group.

<CodeBlock
	title="astro.config.mjs sidebar section"
	lang="js"
	code={String.raw`sidebar: [
	{
		label: 'Guides',
		items: [{ autogenerate: { directory: 'guides' } }],
	},
	{
		label: 'Operations',
		items: [{ autogenerate: { directory: 'operations' } }],
	},
	{
		label: 'Reference',
		items: [{ autogenerate: { directory: 'reference' } }],
	},
]`}
/>

After that, `src/content/docs/operations/runner-health.mdx` appears under Operations and builds as `/operations/runner-health/`.
