This tutorial walks an operator from "I have a packaged app in a repo" to "I am running it in Screens, watching it work, and editing its layout." Each step links to the feature guide where the full surface lives.

<PipelineGraph workflow="capture-to-screens" activeNode="screens" />

## Step 1 — Find the app in the gallery

Open **Screens** in the top nav. The [Application Gallery](/guides/screens/application-gallery/) shows every packaged app as a card with its status badge, version, and three-dot action menu.

If you do not see your app, confirm it was built with target profile `ria-screens` (Composer) and that its manifest is committed at `screens/<app-name>/manifest.json` in the source repo.

## Step 2 — Bind a remote agent (only if needed)

If the app's manifest declares `dataSource.type` as `sdr` or `agent`, the Start button stays disabled until you bind an online agent. Open [Remote Agents](/guides/screens/remote-agents/) for register and bind instructions. Synthetic-source apps skip this step entirely.

## Step 3 — Start the app

Click the card to open the [App runtime](/guides/screens/app-runtime/), then click **Start**. Status flows from `stopped` to `running`. A yellow banner reminds you of the 10-minute consecutive runtime limit.

The manifest-driven component grid renders above a collapsible log strip. Each tile binds to a named operator in the running pipeline.

## Step 4 — Edit the layout in Studio (optional)

Open the gallery card's three-dot menu and pick **Edit in Studio** to open [Screens Studio](/guides/screens/studio/). Swap a component, drop a new tile, fix missing props, then **Save** — Studio bumps the manifest patch version and commits the change. The runtime view picks the new manifest up on its next load; no rebuild required.
