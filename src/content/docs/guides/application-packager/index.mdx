The **Application Packager** turns a trained model artifact into a deployable RIA Hub application. You compose a pipeline graph on a canvas, choose a runtime target, and commit a generated application JSON back to a repository. For the RIA Hub Screens target, the Packager also produces a Screens manifest and tarball so the app is ready to run.

Screens is one of several build targets — the Packager can also produce Holoscan inference applications for NVIDIA, generic CPU, ARM64, and ARM32 runtimes.

## Prerequisites

- A **trained model artifact** in a RIA Hub repository — see [Train a Model](/guides/model-builder/train-a-model/). For most workflows this is a `.onnx` file.
- **Write access** to the target build repository that will receive the application JSON.
- A **target profile** decision. The Composer defaults to `ria-screens`; choose another profile only if you are packaging for a Holoscan runtime.

## How it works

The Packager sits between Model Builder and the runtime stages of the pipeline. It consumes a trained artifact, packages it with a pipeline graph that describes how data flows through it, and writes the result back to a repository the runtime can pull from. Screens picks up the manifest immediately; Holoscan targets feed downstream build infrastructure.
