**RIA Screens** is the browser-side runtime that runs packaged RIA Hub applications. A packaged app is a manifest plus a model bundle: Screens reads the manifest, lays out tiles in a 12-column grid, attaches each tile to its named pipeline operator, and pipes live data through SSE streams. Studio edits the same manifest in place; remote agents feed live SDR data when an app needs it.

| Module | What it does |

## Prerequisites

- A **packaged Screens app** committed to a repository — see [Application Composer](/guides/application-packager/application-composer/).
- **Read access** to the source repository so Screens can fetch the manifest. **Write access** is required if you intend to edit the manifest in Studio.
- For apps whose manifest sets `dataSource.type` to `sdr` or `agent`, at least one **registered remote agent** with the matching hardware online — see [Remote Agents](/guides/screens/remote-agents/).

## The Screens manifest

Every packaged app stores its layout at `screens/<app-name>/manifest.json` in its source repository. The manifest declares the component tree the runtime renders, the data source it binds to, optional preprocessing, and any models the app ships. The [Application Composer reference](/guides/application-packager/application-composer-reference/#the-screens-build-path) documents the manifest schema and how the Composer generates it.

## How it works

Screens sits at the right edge of the Capture → Curate → Train → Package → Run pipeline. It consumes the manifest the Application Composer wrote, attaches its tiles to the live pipeline running under the controller, and streams status and metrics back to your browser.
