# PLAN: Reusable Interactive Docs Components for RIA Hub Docs

Status: planning only. This file is the implementation brief for the next agent. Do not do additional discovery unless a referenced file has moved or a build command fails with new information.

## 1. Goal

Add a reusable component system to this Starlight docs repo so docs authors can keep adding normal Markdown/MDX pages while selectively embedding high-quality Astro components and Svelte 5 islands for interactive learning.

The docs should not feel like a run-of-the-mill docs site. The design direction is a "radio intelligence lab": precise panels, signal visuals, workflow maps, status chips, and guided interactive blocks that explain how a user moves through RIA Hub from onboarding to capture/synthesis, curation/labeling, training, packaging, and Screens apps.

## 2. Non-Goals

- Do not replace Starlight. Keep the current docs shell, search, sidebar, routing, and content collections.
- Do not port the RIA Hub Vue application into the docs. Extract reusable documentation patterns, data models, copy requirements, and visual ideas only.
- Do not hydrate static content. Astro components should be the public authoring API; Svelte should be used only behind Astro wrappers for true interactivity.
- Do not copy MakerFirst branding or RIA Hub app-only provider icons into the docs. Copy structure and useful assets/patterns, not unrelated brand collateral.

## 3. Current Repo Baseline

- `package.json:1-17` currently has Astro, Starlight, and Sharp only. Svelte support must be added.
- `astro.config.mjs:1-30` currently uses only the Starlight integration with GitHub social and autogenerated `guides`/`reference` sidebar groups.

## 4. External and Reference Sources

Use these sources directly; do not re-research them.

- Design.md format specification: https://raw.githubusercontent.com/google-labs-code/design.md/refs/heads/main/docs/spec.md. The spec says a `DESIGN.md` file has optional YAML frontmatter for machine-readable tokens and a Markdown body with sections ordered as Overview, Colors, Typography, Layout, Elevation, Shapes, Components, and Do's/Don'ts.
- LuckyMedia YouTube embed guidance: https://www.luckymedia.dev/blog/building-a-high-performance-youtube-embed-in-astro. Key implementation pattern: render a thumbnail/play button first, keep YouTube iframe out of the DOM until activation, then create an iframe with `allow`, `allowFullscreen`, `loading="lazy"`, and `referrerPolicy="strict-origin-when-cross-origin"`.
- Astro Svelte integration docs: https://docs.astro.build/en/guides/integrations-guide/svelte/. Use `@astrojs/svelte` for Svelte components in Astro.
- Astro framework components/client directives docs: https://docs.astro.build/en/guides/framework-components/. Use Astro client directives only on island components that need browser interactivity.
- Starlight CSS/theming docs: https://starlight.astro.build/guides/css-and-tailwind/. Use Starlight `customCss` and CSS custom properties before introducing Tailwind.

Keep the docs site simple for authors and explicit for component implementers.

```text

  components/
    docs/
      CalloutPanel.astro
      CollapsibleList.astro
      InteractiveCards.astro
      MetricGraph.astro
      PipelineGraph.astro
      SectionCard.astro
      SignalMeter.astro
      StatCard.astro
      StatusLight.astro
      TerminalCard.astro
      YouTubeEmbed.astro
    islands/
      CollapsibleListIsland.svelte
      InteractiveCardsIsland.svelte
      MetricGraphIsland.svelte
      PipelineGraphIsland.svelte
    media/
      youtube.ts
    data/
      docsWorkflows.ts
      onboarding.ts
      trainingExamples.ts
  styles/
    ria-docs.css
```

Public API rule:

- MDX authors import only from `src/components/docs/*.astro`.
- Astro wrapper components decide whether to render static HTML or mount a Svelte island.
- Svelte islands live under `src/components/islands/` and should not be imported directly in docs pages.

Hydration rule:

- Use no directive for static Astro components.
- Use `client:visible` for below-the-fold interactive cards, collapsible filters, and graphs.
- Use `client:idle` for non-critical small enhancements when initial visibility is likely.
- Use `client:load` only if an above-the-fold component is unusable without JavaScript. Avoid this for the first pass.

1. Install Svelte support.

```sh
npm install @astrojs/svelte svelte
```

2. Add `svelte.config.js`, modeled after `repos/MakerFirst3DP.github.io/svelte.config.js:1-5`.

```js
import { vitePreprocess } from '@astrojs/svelte';

export default {
  preprocess: vitePreprocess(),
};
```

3. Update `astro.config.mjs`.

```js
import svelte from '@astrojs/svelte';
```

Then change integrations to include `svelte()` and add Starlight custom CSS:

```js
integrations: [
  svelte(),
  starlight({
    title: 'RIA Hub Docs',
    customCss: ['./src/styles/ria-docs.css'],
```

```json
  "extends": "astro/tsconfigs/strict",
```

## 9. MDX Authoring Contract

Docs authors should keep writing ordinary Markdown unless a page needs a component. For interactive pages, use one import per component and pass plain objects.

Example:

```mdx
---
title: Curate and Label a Radio Dataset
description: Turn captured or synthetic recordings into a training-ready dataset.
---

import PipelineGraph from '@components/docs/PipelineGraph.astro';
import CollapsibleList from '@components/docs/CollapsibleList.astro';
import YouTubeEmbed from '@components/docs/YouTubeEmbed.astro';

<PipelineGraph workflow="capture-to-screens" activeNode="curate" />

<CollapsibleList
  title="Before you curate"
  items={[
    { title: 'Recording is in the Library', body: 'Confirm the recording is tracked with Git LFS and has an OID.' },
    { title: 'Labeling goal is known', body: 'Define modulation classes, device classes, or scenario labels before slicing.' },
  ]}
/>

<YouTubeEmbed id="VIDEO_ID" title="Curating an example radio problem" />
```

Rules:

- Prefer `.md` for prose-only docs.
- Use `.mdx` only when embedding docs components.
- Do not write inline `<script>` tags in MDX.
- Do not import Svelte islands directly from MDX.
- Keep component data local for one-off examples, but move shared workflow data into `src/data/*.ts`.

## 10. First Component Set

### 10.1 `YouTubeEmbed.astro`

Purpose: high-performance video embed for training and onboarding material.

Files:

- `src/components/docs/YouTubeEmbed.astro`
- `src/components/media/youtube.ts`

Props:

- `id?: string`
- `src?: string`
- `title: string`
- `caption?: string`
- `poster?: string`
- `start?: number`
- `aspectRatio?: '16:9' | '4:3' | '1:1'`
- `privacyEnhanced?: boolean` default `true`

Behavior:

- Accept either a YouTube video ID or a full YouTube URL.
- Parse and validate the video ID in `youtube.ts`.
- Render thumbnail and button only at first paint.
- Use `https://www.youtube-nocookie.com/embed/${id}` when `privacyEnhanced` is true.
- Add `autoplay=1` only after user activation.
- Add preconnect links dynamically on `pointerenter` and `focus`.
- Replace the root children with an iframe only on click/Enter/Space.
- Use iframe attributes from the LuckyMedia pattern: `allow`, `allowFullscreen`, `loading="lazy"`, `referrerPolicy="strict-origin-when-cross-origin"`.
- Provide a noscript link to the video.

Accessibility:

- Button label must include the title, e.g. `Play video: Training run walkthrough`.
- Iframe title must match the `title` prop.
- Caption renders as visible text below the video.

Acceptance:

- Before click, no `iframe` appears in built HTML.
- After click, video loads and can be fullscreened.
- Keyboard activation works.
- Lighthouse should not report YouTube network requests before activation.
